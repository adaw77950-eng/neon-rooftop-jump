# 霓虹跃迁 Cocos Creator 迁移设计

## 目标

把现有浏览器 Canvas 原型迁移为 Cocos Creator 3.8 LTS 的 2D TypeScript 工程，第一阶段保持玩法一致：像素风屋顶、长按蓄力、松开起跳、重力抛物线、落点判定、连续完美、无限生成平台、手机触控与电脑鼠标。

## 推荐架构

采用“纯玩法内核 + Cocos 表现层”。`GameMath.ts` 只处理蓄力、弹道、落点与平台生成，不引用 Cocos API，因此可以直接单元测试。`NeonJumpGame.ts` 是唯一的启动组件，负责输入、状态机、节点创建、摄像机跟随、UI、存档和音效。场景只保留 Canvas、Camera 与启动节点，运行后自动生成所有像素节点，避免迁移初期依赖外部图片和复杂 Prefab。

首版使用 Cocos 原生 `Graphics` 绁制角色、平台、城市、雨和 HUD。这样工程开箱即可运行，也保持清晰的像素块风格。后续美术资源稳定后，再把对应节点替换为 SpriteFrame/图集，不改玩法内核。

坐标使用 Cocos 世界坐标：向右为正、向上为正。旧网页的向下 Y 坐标会在表现层转换。跳跃仍采用线性水平位移和二次抛物线竖直位移，保证刚刚调好的手感不丢失。

## 输入与状态

状态机为 `idle → charging → jumping → idle/falling → gameover`。鼠标和触摸统一监听 `Input.EventType.TOUCH_START/END/CANCEL`；键盘空格作为桌面辅助输入。应用失焦时取消蓄力，防止回到游戏后自动起跳。

## 数据与扩展

最佳分数与静音设置存入 `sys.localStorage`。平台难度随分数逐步增加。每日挑战、皮肤、任务、英语界面和商业化接口暂不在第一阶段实现，但目录和状态设计允许之后加入 `systems/`、`data/` 与资源包，不需要重写核心玩法。

## 验收

1. Node 单测覆盖蓄力范围、抛物线、落点和平台可达性。
2. Cocos Creator 3.8 LTS 能识别工程并打开 `main.scene`。
3. 浏览器预览支持长按鼠标；手机预览支持长按屏幕。
4. 首次三跳可达，失败后能重开，最佳分数可保存。
